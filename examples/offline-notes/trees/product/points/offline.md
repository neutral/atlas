# Offline work stays on the current device

A writer can create and revise notes without a connection. Before they close
the app, the interface shows whether a change is still being saved or has been
saved on this device. A note saved this way is there when the app is closed
and reopened normally, still offline. The brief's [offline work
section](../../../sources/brief.md#offline-work) states these requirements.

What the writer gains is limited to this device. A note saved offline has not
reached a server or any other device. The brief's [delivery
states](../../../sources/brief.md#save-and-delivery-states) exist so that a
writer does not take a local save for a copy somewhere else, and [the wording
decision](promise.md) says how the app keeps that distinction in its words.

The evidence for this promise is narrow. One trial reopened a note after a
normal restart; a forced close, a crash and power loss were not tested.
[The offline promise rests on one normal restart](../facets/local-limit.md)
says what that means for this claim. The brief [leaves these
open](../../../sources/brief.md#what-remains-to-be-established), together with
the implementation itself.
