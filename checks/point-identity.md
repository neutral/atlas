# Review Point identity before creation

## Requirement

For each new anchor or changed identity decision, record why the item needs independent reference and how it differs from the nearest existing Points. Apply the core Point definition; shared subject matter is not shared identity. Reuse an id only for the same item, not merely the same technology, document, or topic.

## Verification

Search the authorized Atlas by id, wording, sources, and related context. Inspect candidate anchors, scope, and local records. Explain why the change updates the same item, adds its Map-local significance, or establishes a separately standing claim. A decision and its rollout status remain separate when their states can differ. Supporting rationale and examples need no separate identity merely because their sentences differ. Report a limited search rather than claiming exhaustive uniqueness.

## Failure

Fail when an identity decision lacks a defensible distinction, duplicates an existing item, combines claims with incompatible standing, or uses another id to evade context constraints. Resolve the distinction or leave it explicit and uncommitted. Do not force same-subject claims into one Point or invent a Point for every source sentence.
