# Contributing to Atlas

Email [info@neutral.dev](mailto:info@neutral.dev) before preparing a material specification change. This lets maintainers identify the owning contract and the evidence that must change with it.

## Change expectations

- Give each requirement one owning specification document.
- Keep conceptual prose, normative requirements, terminology, schemas, examples, fixtures, diagnostics, and normalized output consistent.
- Use short, active, declarative technical prose.
- Use uppercase BCP 14 keywords only for normative requirements.
- Preserve stable identifiers unless the represented subject changes.
- Add or update valid and invalid fixtures for observable behavior.
- Keep malformed fixture bytes and filenames intact when they are part of the expected result.
- State the compatibility effect of a format change. Revision 0.7.0 is pre-1.0, so breaking changes remain possible.
- Do not submit credentials, personal data, confidential material, or third-party material that you cannot distribute.
